将完整 ZIP 导入宿主的技能安装入口，或让宿主按其支持方式从附件读取并安装。须确认 SKILL.md、scripts、assets、templates 和 schemas 全部保留；仅粘贴 SKILL.md 不构成脚本安装。

安装后第一条指令：

> 使用工程微创新孵化平台 Skill。先定位实际安装目录，检查 scripts/run.py 和 assets 是否存在。运行 probe 到新目录，交付 probe.json 和 probe-download.zip 的可下载附件。不要把写入沙箱成功说成用户已下载。若 Python 被禁止或不存在，请如实输出“只能使用思考模式”，不要生成虚假链接。

## 固定参数三次（隔离脚本确定性）

> 使用 Skill 中 assets/case001/input.example.json，不更改任何参数或文字，分别生成 run1、run2、run3，每次使用新目录。每次运行 verify。比较三次所有成果文件的 SHA-256，列出差异。把完整输出打包为可下载附件，至少单独附上 HTML、效果图、Excel 和校核报告。记录 Python 版本及失败日志。不要使用 AI 绘图或桌面软件。

## 同一自然语言需求三次（验收 AI 到成果的完整链）

在三个独立会话中原样发送，不沿用上次生成的参数文件：

> 使用工程微创新孵化平台 Skill，按 CASE-001 下倒角既有布局生成评审草案。压板厚 10 mm、销轴直径 20 mm、钢管 Φ48×3.5 mm，其他支持的尺寸采用案例中明确标注的设计假设。现场荷载、材料牌号和规范原文尚未提供，保留待复核。输出方案、工法、专利交底和 QC 四种草案。请先保存本次独立整理的 input JSON，再运行脚本、校核并提供文件下载。不使用 AI 绘图，不手写清单数量。

保存每轮 prompt、AI 整理的 JSON、canonical JSON、manifest、日志及下载的 ZIP。比较维度分开：①9 个数值参数是否相同；②几何/清单是否相同；③输入文本/Word 是否相同；④全部文件字节是否相同。不要将文字差异改写成“完全一致”。如参数漂移，先固定参数决策表与默认值确认规则，再重新测试。
